# 00. 구글 알고리즘 분석 — 무엇이 순위를 만드는가

> 이 문서는 "무엇을 최적화할 것인가"의 근거다. 뒤의 모든 기획·세팅은 여기서 정리한 신호(signal)를 채우는 작업이다.

## 1. 대전제 3가지

1. **구글 순위는 API로 바꿀 수 없다.** 유료든 무료든 "순위를 직접 올리는" 인터페이스는 존재하지 않는다. 우리가 하는 일은 구글이 읽는 신호를 정확하고 완전하게 채워 넣어, 알고리즘이 우리를 정답으로 고르게 만드는 것이다.
2. **웹 검색과 구글맵(로컬)은 다른 알고리즘이다.** 랭킹 요소가 다르므로 두 축을 나눠 기획해야 한다. 소상공인은 대부분 **로컬(구글맵) 쪽 ROI가 훨씬 크다.**
3. **효과는 지연된다.** 세팅 → 크롤링/인덱싱 → 사용자 행동 누적 → 순위 반영까지 보통 4~12주. 1~2주 만에 판단하면 잘못된 의사결정을 한다.

---

## 2. 웹 검색 알고리즘 구조

### 2-1. 3단계 파이프라인

| 단계 | 하는 일 | 여기서 탈락하는 이유 |
|---|---|---|
| **크롤링(Crawling)** | Googlebot이 페이지를 발견·수집 | robots.txt 차단, 링크 고아 페이지, 무한 로딩 JS |
| **인덱싱(Indexing)** | 내용을 해석해 색인 저장 | `noindex`, 중복 콘텐츠(canonical 미설정), 내용 없는 페이지 |
| **서빙/랭킹(Serving)** | 쿼리에 맞춰 순서 결정 | 관련성·품질·사용성 신호 부족 |

**핵심**: 순위 이전에 "색인되어 있는가"가 먼저다. Search Console의 페이지 색인 리포트가 1차 점검 지점이다.

### 2-2. 랭킹을 결정하는 5개 축 (구글이 공개한 프레임)

| 축 | 구글이 보는 것 | 우리가 통제 가능한 실행 |
|---|---|---|
| **의미 파악(Meaning)** | 검색어의 의도·동의어·언어·오타 해석 | 사용자가 실제로 치는 표현으로 쓰기 (키워드 리서치의 존재 이유) |
| **관련성(Relevance)** | 페이지가 그 의도에 답하는가 | 타이틀/H1/본문/이미지 alt에 대상 키워드와 그 주변 개념 배치 |
| **품질(Quality)** | 경험·전문성·권위·신뢰(E-E-A-T), 피인용/링크 | 실제 경험 기반 콘텐츠, 사업자 정보 명시, 외부 언급·링크 확보 |
| **사용성(Usability)** | 모바일 대응, 속도(Core Web Vitals), HTTPS, 침입형 광고 없음 | LCP 2.5초 이하 / INP 200ms 이하 / CLS 0.1 이하 |
| **맥락(Context)** | 사용자의 위치·언어·검색 이력 | 지역명 결합 키워드, 한/영 이중언어 대응 |

### 2-3. 2024년 이후 바뀐 것 (기획에 반드시 반영)

- **Helpful Content 시스템이 코어 알고리즘에 통합**되었다. "검색엔진용으로 만든 글"은 사이트 전체 평가를 끌어내린다. → 페이지 수를 늘리는 전략보다 **적은 수의 진짜 유용한 페이지**가 유리하다.
- **INP가 FID를 대체**해 Core Web Vitals 지표가 되었다. 상호작용 반응성이 실측된다.
- **AI 개요(AI Overviews)** 가 상단을 차지하면서, 정보성 키워드의 클릭률은 떨어지고 **"지금 사겠다/가겠다"는 로컬·거래 의도 키워드의 가치가 상대적으로 올라갔다.** → 소상공인은 정보성 블로그보다 로컬 전환 키워드에 집중하는 게 맞다.

## 3. 구글맵(로컬) 알고리즘 — 소상공인의 주전장

구글이 공식적으로 밝힌 로컬 랭킹 요소는 **딱 3개**다.

### 3-1. 관련성 (Relevance) — *통제 가능, 최우선*
검색어와 우리 비즈니스 프로필이 얼마나 정확히 맞는가.

| 신호 | 구체 실행 |
|---|---|
| 기본 카테고리 | 매출 핵심을 가장 정확히 설명하는 **1개**만. 여러 개 걸면 관련성이 흐려진다 |
| 보조 카테고리 | 최대 9개, 실제 제공하는 것만 |
| 서비스/메뉴 항목 | 개별 등록 (각각이 검색 매칭 단위가 된다) |
| 비즈니스 설명 (750자) | 핵심 키워드 + 지역명을 자연스러운 문장으로 |
| 속성(Attributes) | 주차, 배달, 휠체어 접근, 결제수단 등 — 필터 검색 노출에 직결 |
| 게시물(Posts)·Q&A·사진 파일명 | 키워드가 등장하는 추가 표면 |

### 3-2. 거리 (Distance) — *통제 불가*
검색자 위치(또는 검색어에 포함된 지역)와 매장까지의 실제 거리. **조작할 수 없다.** 허위 주소·가상 오피스 등록은 프로필 정지 사유다.
→ 대신 **"어느 지역명으로 잡히느냐"** 를 관리한다. 인접 상권 지역명은 주소가 아니라 *콘텐츠·서비스 지역·게시물*로 커버한다.

### 3-3. 인지도 (Prominence) — *통제 가능, 장기전*
그 지역에서 얼마나 잘 알려진 곳인가.

| 신호 | 실행 |
|---|---|
| 리뷰 **개수** | 지속적·자연스러운 유입 (한 번에 몰아 받으면 스팸 판정) |
| 리뷰 **평점** | 4.0 이상 유지, 낮은 평점엔 반드시 사장 답글 |
| 리뷰 **최신성** | 3개월 이상 리뷰 공백 = 감점 신호 |
| 리뷰 **본문 키워드** | 고객이 "포트무디 김치찌개 맛집"처럼 써주면 관련성까지 동시 상승 |
| 웹 언급/인용(Citation) | 디렉토리·지역 매체·블로그에서 NAP가 동일하게 언급되는 횟수 |
| 웹사이트 SEO 점수 | 연결된 웹사이트의 웹검색 랭킹이 로컬 인지도에 반영된다 |
| 사용자 행동 | 경로 요청, 통화 클릭, 웹사이트 클릭, 사진 조회 |

### 3-4. NAP 일관성 — 인지도의 전제 조건
Name / Address / Phone 이 모든 채널에서 **한 글자도 다르지 않아야** 구글이 같은 업체로 합산한다.
`Port Moody` vs `Port Moody, BC` vs `포트무디` 혼용은 신호가 3등분되는 것과 같다.

## 4. 하면 안 되는 것 (프로필 정지 리스크)

| 금지 행위 | 결과 |
|---|---|
| 상호명에 키워드 끼워넣기 (`OO식당 | 밴쿠버 최고 한식`) | 프로필 정지 또는 상호 강제 수정. 실제 간판과 동일해야 한다 |
| 리뷰 대가 제공(할인·사은품) | 구글 리뷰 정책 위반, 리뷰 일괄 삭제 |
| 가짜 리뷰 / 지인 대량 리뷰 | 필터링 + 프로필 신뢰도 하락 |
| 실제로 운영하지 않는 주소 등록 | 정지 |
| 키워드 스터핑 콘텐츠 | Helpful Content 신호로 사이트 전체 하락 |

## 5. 결론 — 이 프로젝트가 최적화할 신호 목록

```
[웹 검색]
  색인 가능성 → 관련성(키워드 배치) → 품질(E-E-A-T) → 사용성(CWV)

[구글맵]
  관련성(카테고리·설명·서비스·속성)   ← 1주 안에 완료 가능, 즉효
  거리(주소·서비스 지역)               ← 고정값, 관리만
  인지도(리뷰·인용·웹SEO·행동신호)     ← 4~12주 누적, 장기 과제
```

**우선순위 원칙**: *통제 가능 × 즉효* 인 **관련성**을 1주차에 100% 채우고, 그다음 **인지도**를 12주에 걸쳐 쌓는다.
