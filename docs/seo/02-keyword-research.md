# 02. 키워드 리서치 — 구글 키워드 플래너 실전

## 0. 먼저 알아야 할 한계

**AI는 검색량을 만들어내지 않는다.** 검색량·경쟁도·CPC는 반드시 실제 툴에서 뽑은 값만 사용한다. 추정으로 만든 숫자로 의사결정하면 없는 수요에 페이지와 예산을 태우게 된다.

이 프로젝트는 두 모드로만 동작한다.
- **모드 1 (데이터 있음)**: CSV를 `data/keywords/`에 넣고 점수화 → 확정 우선순위표
- **모드 2 (데이터 없음)**: 씨앗 키워드까지만 만들고, 아래 절차로 실측을 뽑아온 뒤 모드 1로 전환

---

## 1. Google Keyword Planner 데이터 뽑기 (무료)

### 1-1. 계정 준비
1. `ads.google.com` 접속 → 구글 계정으로 로그인
2. 캠페인 생성 화면이 뜨면 하단 **"전문가 모드로 전환"** (Switch to Expert Mode) 클릭
3. **"캠페인 없이 계정 만들기"** 선택 → 결제수단 등록 없이 계정 생성 완료
4. 상단 메뉴 **도구(Tools) → 계획(Planning) → 키워드 플래너**

> 광고를 집행하지 않아도 조회 가능하다. 단, **미집행 계정은 검색량이 구간값**(예: "100~1천")으로만 표시된다. 이 프로젝트의 점수화 툴은 구간을 **하한값으로 보수적 처리**한다.

### 1-2. 조회 설정 (이 3가지를 반드시 맞춘다)
| 설정 | 값 | 이유 |
|---|---|---|
| **위치(Location)** | 우리 도시 단위로 지정 (국가 전체 ❌) | 로컬 수요만 봐야 한다. 국가 단위는 우리와 무관한 수요가 섞인다 |
| **언어(Language)** | 한국어 + 영어 **각각 따로 2회 조회** | 한 번에 섞으면 언어별 수요를 구분 못 한다 |
| **검색 네트워크** | Google (검색 파트너 제외) | 노이즈 제거 |

### 1-3. 씨앗 키워드 입력
"**새 키워드 찾기(Discover new keywords)**" 에 아래 3유형을 각각 넣는다.

| 유형 | 형태 | 예시 |
|---|---|---|
| 서비스 + 지역 | `[업종] [도시명]` | `한식당 포트무디`, `korean restaurant Port Moody` |
| 일반 탐색형 | `[업종] near me`, `[도시] 맛집` | `korean food near me`, `밴쿠버 맛집` |
| 세부 니즈(롱테일) | `[메뉴/시술/과목] [도시]` | `김치찌개 배달 밴쿠버`, `korean bbq takeout` |

### 1-4. 내보내기
결과 화면 우측 상단 **다운로드 → CSV(.csv)** → 파일을 `data/keywords/` 폴더에 저장.
파일명 규칙: `kp-<지역>-<언어>-<YYYYMM>.csv` (예: `kp-portmoody-ko-202608.csv`)

> 플래너 CSV는 상단에 안내 2~3줄이 붙어 있고 UTF-16/탭 구분인 경우가 있다. **점수화 툴이 자동으로 감지·처리**하므로 파일을 손대지 말고 그대로 넣는다.

## 2. 보조 데이터 소스

| 툴 | 얻는 것 | 한계 |
|---|---|---|
| **Google Trends** | 계절성·상대 추세, 지역별 관심도 비교 | 절대 검색량 없음 |
| **Search Console** | 우리 사이트가 **실제로 노출된** 검색어 (가장 정확) | 사이트 운영 후에만, 데이터 누적 필요 |
| **GBP 인사이트** | 고객이 우리 프로필을 찾은 검색어 | 로컬 한정, 표본 적음 |
| **네이버 검색광고 키워드도구** | 한국어 키워드 월간 검색수 | **한국 국내 기준** — 해외 교민 상권엔 방향성 참고만 |
| **구글 자동완성 / 함께 검색한 항목** | 실제 사용 표현, 롱테일 발굴 | 수치 없음 |

> **가장 강력한 소스는 3개월 뒤의 Search Console이다.** 초기엔 Keyword Planner로 시작하고, 데이터가 쌓이면 GSC 실측으로 키워드맵을 갱신한다.

## 3. 검색 의도(Intent) 분류 — 점수화의 핵심 입력

같은 검색량이라도 의도에 따라 가치가 4배 이상 차이 난다.

| 의도 | 정의 | 예시 | 가중치 |
|---|---|---|---|
| **local** | 지금 갈 곳/살 곳을 찾음 | `포트무디 한식당`, `korean restaurant near me` | **1.00** |
| **transactional** | 구매·예약·주문 직전 | `김치찌개 배달`, `online booking` | 0.95 |
| **commercial** | 비교·검토 중 | `best korean bbq vancouver`, `한식당 추천` | 0.80 |
| **informational** | 정보만 찾음 | `김치찌개 만드는 법` | 0.45 |
| **brand** | 우리/경쟁사 상호 검색 | `OO식당` | 0.35 |

**소상공인 원칙: local + transactional에 자원의 70%를 쓴다.** 정보성 키워드는 AI 개요에 답을 뺏겨 클릭이 나오지 않는다.

의도는 툴이 키워드 패턴으로 **자동 추정**하며, `data/keywords/intent-overrides.csv`로 수동 교정할 수 있다.

---

## 4. 관련성(Relevance) — 사람이 판단해야 하는 유일한 값

검색량이 아무리 커도 **우리가 실제로 팔지 않는 것**이면 0점이다.

| 값 | 기준 |
|---|---|
| `1.0` | 우리 핵심 상품/서비스 그 자체 |
| `0.7` | 우리가 취급하지만 주력은 아님 |
| `0.4` | 간접적으로만 연결 |
| `0` | 우리와 무관 → 제외 |

`data/business.profile.json`의 `services`·`excludeTerms`를 기준으로 툴이 1차 자동 판정하고, `relevance-overrides.csv`로 교정한다.

---

## 5. 산출 후 처리 규칙

1. **검색량 0 키워드는 버리지 않고 별도 섹션에 남긴다** — "실측 수요 없음" 근거로 보관. 나중에 같은 키워드를 다시 제안받는 낭비를 막는다.
2. **경쟁사 브랜드 검색이 잡히면** 직접 타깃하지 않는다. 우리 차별점 문구의 근거로만 쓴다. (상표권 이슈)
3. **한국어 키워드는 검색량이 작아도 버리지 않는다** — 언어가 일치하는 고객은 전환율이 훨씬 높다. 툴의 `--minority-language-boost` 옵션으로 보정한다.
