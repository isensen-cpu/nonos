# 08. 복합 업종 + 신규 등록 실행서 (북미 한인 상권)

> 적용 조건: **캐나다/북미 한인 상권 · 여러 업종이 한 사업장에 결합 · GBP 미등록 · 웹사이트 없음**
> 이 조건에서는 04번(기술 SEO)을 건너뛰고 **구글맵 하나에 집중**하는 것이 맞다. 웹사이트 없이도 로컬 팩 진입이 가능하다.

---

## 1. 복합 업종의 근본 딜레마

구글은 **하나의 사업장 = 하나의 정체성**으로 이해한다. 음식·뷰티·리테일·교육을 한 프로필에 동등하게 걸면 관련성 점수가 4등분되어 **어느 것으로도 상위에 못 잡힌다.**

| 잘못된 접근 | 결과 |
|---|---|
| 4개 업종의 기본 카테고리를 다 넣고 싶어함 | 기본은 1개만 가능. 억지로 넓은 카테고리를 고르면 관련성 붕괴 |
| 업종별로 프로필을 4개 만듦 | 중복 프로필 = 정지 사유 (아래 3장의 예외 조건 충족 시에만 가능) |
| 상호명에 "한식·뷰티·마트"를 나열 | 키워드 스터핑 = 정지 |

**정답: 매출 1순위 업종으로 정체성을 잡고, 나머지는 보조 카테고리 + 서비스 항목 + 게시물로 커버한다.**

---

## 2. 기본 카테고리 결정 트리

```
Q1. 지난 3개월 매출에서 가장 큰 업종은?
        │
        ▼
  그 업종의 "가장 좁고 정확한" 카테고리 1개 = 기본 카테고리
        │
        ▼
Q2. 나머지 업종은?
        │
        ├─ 각 업종의 카테고리를 보조로 등록 (전체 합쳐 최대 9개)
        ├─ 각 업종의 상품/서비스를 **서비스 항목**으로 개별 등록  ← 여기가 진짜 승부처
        └─ 각 업종을 게시물 로테이션에 배치
```

**중요**: 보조 카테고리 9개를 억지로 다 채우지 않는다. **실제로 제공하는 것만** 넣는다. 관련 없는 카테고리는 기본 카테고리의 관련성을 희석시킨다.

### 업종별 카테고리 후보

| 업종 | 기본 후보 (하나만 선택) | 보조 후보 |
|---|---|---|
| 음식점·카페·베이커리 | `Korean Restaurant` | Restaurant, Barbecue Restaurant, Asian Restaurant, Cafe, Bakery, Coffee Shop, Dessert Shop, Takeout Restaurant |
| 뷰티·헤어·네일 | `Beauty Salon` / `Hair Salon` / `Nail Salon` | Facial Spa, Skin Care Clinic, Eyelash Salon, Waxing Hair Removal Service |
| 리테일·마트 | `Asian Grocery Store` / `Cosmetics Store` / `Gift Shop` | Grocery Store, Food Store, Beauty Supply Store, Novelty Store |
| 교육·학원 | `Language School` / `Tutoring Service` | Education Center, Learning Center, After School Program |
| K-컬처 체험 | `Amusement Center` / `Karaoke Bar` | Photo Booth, Gift Shop, Tourist Attraction, Event Venue |

> ⚠️ 카테고리 목록은 구글이 주기적으로 갱신한다. `Korean Grocery Store` 처럼 원하는 명칭이 없으면 **목록에 있는 것 중 가장 구체적인 것**으로 대체한다. 등록 화면에서 영문 업종명을 입력하면 실시간으로 후보가 뜬다.

## 3. 프로필을 나눠도 되는 경우 (예외)

아래 **두 조건을 모두** 충족할 때만 별도 프로필이 허용된다.

1. 법적으로 **별개 사업자**이고 (별도 사업자등록·별도 상호)
2. 물리적으로 **구분된 출입구·공간**을 쓰며, 각각 **전용 직원**이 상주

한 공간에서 사장 한 명이 여러 업종을 운영하는 구조라면 **프로필은 하나**다. 나누면 중복 프로필로 정지된다.

## 4. 신규 등록 절차 (미등록 상태 → 첫 노출까지)

### 4-1. 등록 전 준비물
- [ ] 사업자 증빙 (Business License / GST 등록증)
- [ ] 간판이 설치된 상태 (동영상 확인에 필수)
- [ ] 상호명 최종 확정 — **간판·라이선스와 100% 동일한 문자열**
- [ ] 대표 전화번호 1개 (개인 휴대폰이어도 무방하나, 이후 모든 채널에서 동일하게 사용)
- [ ] 사진 20장 (`checklists/photo-specs.md` 규격대로 미리 촬영)

### 4-2. 등록 → 인증
1. `business.google.com` → 비즈니스 검색 → **이미 자동 생성된 프로필이 있는지 먼저 확인**
   (구글이 지도 데이터로 임의 생성해둔 경우가 있다. 있으면 신규 생성이 아니라 **소유권 주장**)
2. 카테고리 입력 → **기본 1개** (2장의 결정 트리 결과)
3. 주소 입력 → 지도 핀을 **실제 출입구**로 드래그
4. 소유권 확인 — 최근 북미 지역은 **동영상 확인**이 기본
   > 끊김 없이 한 번에: 간판 → 주변 거리(위치 식별 가능하게) → 출입구 → 내부 → 영업 도구(주방·시술대·진열대·POS) → 사업자 증빙 서류
   > 실패 시 재신청까지 시간이 오래 걸린다. **촬영 순서를 한 번 연습하고 찍는다.**
5. 승인까지 보통 3~7일. 그 사이에 사진 정리·설명 초안을 준비한다.

### 4-3. 승인 직후 (1주차)
`checklists/gbp-setup-checklist.md` 의 1주차 항목을 그대로 실행.
복합 업종은 특히 **서비스 항목 등록**이 핵심이다 — 업종별로 최소 3개씩, 합계 12개 이상.

## 5. 이중언어(한/영) 전략 — 북미 한인 상권의 핵심

| 항목 | 원칙 |
|---|---|
| **상호명** | 실제 간판 그대로. 간판이 영문이면 영문, 병기면 병기. 임의로 한글을 추가하지 않는다 |
| **비즈니스 설명** | **주력 언어로 먼저 작성**하고 다른 언어를 뒤에 덧붙이지 않는다. 750자 안에서 자연스럽게 섞는 편이 낫다 |
| **키워드 우선순위** | `primaryLanguage` 설정이 결정. 현지인 확장이 목표면 `en`, 교민 기반 다지기면 `ko` |
| **한국어 키워드** | 검색량이 작아도 **버리지 않는다.** 언어가 일치하는 고객은 전환율이 훨씬 높다 (산출기가 1.15배 보정) |
| **사진 파일명** | **반드시 영문.** 구글은 한글 파일명을 텍스트 신호로 잘 읽지 못한다 |
| **리뷰** | 한국어 리뷰와 영어 리뷰가 **둘 다** 있어야 양쪽 검색에 모두 잡힌다. 요청 시 고객 언어에 맞춰 안내 |

## 6. 실행 순서 — 웹사이트 없이 12주

| 시점 | 할 일 | 참조 |
|---|---|---|
| **0주** | `data/business.profile.json` 채우기 → `npm run seo:seeds` | 아래 7장 |
| **0~1주** | 플래너로 씨앗 키워드 조회 → CSV → `npm run seo:score` | `02`, `03` |
| **1주** | 등록·소유권 확인 신청 (동영상 촬영) | 위 4장 |
| **2주** | 승인 후 관련성 세팅 100% (카테고리·설명·서비스 12개·속성·사진 20장) | `05` STEP 2 |
| **3~4주** | 게시물 주 1회, Q&A 5개, 리뷰 QR 비치 | `06` |
| **4~12주** | 리뷰 30개 누적, NAP 인용 10곳, 사진 주 2~3장 | `05` STEP 4 |
| **12주** | KPI 비교 → 키워드맵 갱신 → 필요하면 그때 웹사이트 착수 | `07`, `04` |

> **웹사이트는 12주 뒤에 판단한다.** GBP 인사이트에서 "웹사이트 클릭"을 원하는 수요가 실제로 보일 때 만드는 것이 순서다. 지금 만들면 관리 대상만 늘어난다.

## 7. 지금 바로 실행

```bash
# 1) 프로필의 <> 부분을 실제 값으로 채운다
#    특히: businessName / city / cityEn / nearbyCityPairs / verticals(매출순) / services
vi data/business.profile.json

# 2) 씨앗 키워드 생성 → 플래너 조회용 묶음이 만들어진다
npm run seo:seeds
cat data/keywords/seeds/README.md

# 3) 플래너에서 받은 CSV를 data/keywords/ 에 넣고
npm run seo:score
cat data/keywords/output/keyword-map.md
```

`verticals` 배열의 **맨 앞이 매출 1순위 업종**이어야 한다. 기본 카테고리 선정과 키워드 우선순위가 여기서 갈린다.
